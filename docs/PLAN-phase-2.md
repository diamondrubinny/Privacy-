# תוכנית עבודה — שלב 2: סריקת אתר מלאה

> אושר להמשך: 2026-10-23. מקור: [`SPEC.md`](SPEC.md) §7, §14 ו-[PLAN-phase-0-1](PLAN-phase-0-1.md) "פתוח לשלב 2".

## יעד

אותה פקודה (`pnpm scan <url>`) מחזירה, בנוסף לבדיקת ההסכמה, **audit** של האתר:

1. **Crawler מנומס:** robots.txt, עד 8 דפים, השהיה בין דפים. נבחרים דפים משפטיים (פרטיות, נגישות, תקנון, עוגיות), דף צור קשר ודפי הרשמה ורכישה.
2. **טפסים:** שדות מידע אישי, יידוע ליד הטופס, הסכמה לדיוור, שליחה מאובטחת.
3. **מדיניות פרטיות:** קיום, שפה, רכיבי חובה, תאריך עדכון.
4. **אבטחה:** HTTPS ו-redirect, TLS, HSTS, כותרות אבטחה, mixed content, דגלי עוגיות.
5. **נגישות:** axe-core (WCAG 2.1 AA), הצהרת נגישות, זיהוי "כפתור נגישות" כתחליף.
6. **הקשחה:** Chromium sandbox (כשאפשר) ושדה `scanLocation` בדוח.

## עקרונות

- **Collectors אוספים, כללים מסיקים.** collectors שומרים אותות גולמיים ממוזערים: labels, types, טקסט מדיניות. כל הסיווג (סוג מידע אישי, רכיבי מדיניות) נמצא ב-`packages/rules` עם גרסה, כך שממצא ניתן לשחזור מה-evidence.
- **אין קריאת ערכים** מטפסים, ואין שליחת טפסים.
- robots.txt חל על דפים שהתגלו. דף היעד שהמשתמש ביקש נסרק תמיד.
- כללים שמבוססים על פרשנות משפטית מסומנים "דורש אימות".

## בדיקות

- יחידה: robots, סיווג שדות, רכיבי מדיניות, כל כלל עם evidence סינתטי.
- E2E: אתרי fixture חדשים: `shop.test` (טפסים בעייתיים, מדיניות חסרה ולא מעודכנת, בעיות נגישות, robots שחוסם דף) ו-`secure.test` חדש (מדיניות מלאה, הצהרת נגישות, טופס תקין). ממצאים צפויים מדויקים.

## תוצאות (2026-10-23)

**סטטוס: הושלם.** 161 בדיקות עוברות (unit + E2E), lint, typecheck ו-format נקיים. Ruleset ‏`2026.10.1` כולל 29 כללים בחמש קטגוריות. `A11Y-AXE` מפיק ממצא נפרד לכל כלל axe.

### אתרי בדיקה

- `secure.test` (HTTPS, מדיניות מלאה, טופס עם יידוע, חיפוש דומיין, reCAPTCHA ו-honeypot מוסתרים): **0 ממצאים**.
- `shop.test`: **בדיוק** 17 סוגי הכללים הצפויים. robots.txt נאכף, והדף החסום לא התבקש מהשרת.

### אימות מול אתר אמיתי (box.co.il, אחד ממקורות האפיון)

הסריקה הראשונה החזירה 26 ממצאים. בדיקה ידנית של הראיות מצאה **7 false positives**, וכולם תוקנו ונוספו להם בדיקות רגרסיה:

| בעיה | שורש | תיקון |
|------|------|-------|
| מדיניות פרטיות שגויה (דף מוצר "סורק מדיניות פרטיות") | התאמת טקסט לא מעוגנת | ניקוד: טקסט מדויק > מכיל > URL, ובונוס Footer |
| POL-OUTDATED לפי "בתוקף מאוגוסט 2025" | מילת מפתח גנרית | רק ניסוחי "עודכן לאחרונה" מפורשים |
| "שם דומיין" סווג כשם אדם | "שם" גנרי | שדות לא-אישיים (דומיין, URL, קופון) נבדקים קודם |
| טופס התחברות סווג כאיסוף מידע | textarea מוסתר של reCAPTCHA | התעלמות מפקדים מוסתרים ומ-captcha, וזיהוי איפוס סיסמה |
| "אין redirect ל-HTTPS" (בפועל 301) | שגיאת רשת פורשה כ"אין redirect" | false רק אם http החזיר 2xx. אחרת "לא נקבע" |
| הקשר טופס כלל את כל ה-body | טיפוס בעץ ה-DOM ללא גבול | עצירה ב-landmark, לעולם לא body |
| לחיצת "אישור" נכשלה | overlay חוסם pointer | fallback ל-`dispatchEvent('click')` |

אחרי התיקונים: 19 ממצאים. הממצא שנבדק לעומק (טופס ניוזלטר בלי יידוע) נכון.

### Chromium sandbox

נבדק ב-Docker. פרופיל ה-seccomp של ברירת המחדל חוסם user namespaces, ובמקרה כזה מוחזרת הודעת שגיאה ברורה. עם `seccomp=unconfined`, cap-drop ALL, non-root ו-read-only ה-sandbox עולה והסריקה רצה. ברירת המחדל באימג': פעיל.

### פתוח לשלב 3

- פרופיל seccomp מותאם (במקום unconfined) כחלק מה-deployment.
- Importer ל-Open Cookie Database והרחבת זיהוי CMP (Usercentrics, Sourcepoint).
- תור (BullMQ), DB (Postgres), Web UI עם דוח בעברית, PDF ותזמון.
